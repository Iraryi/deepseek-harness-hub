# Agent Note：显式安装未锁定 Commit 的 GitHub DSHMK 候选

状态：已实现

[English](2026-08-22-unpinned-github-dshmk-install.md) | 中文

## 问题

部分 DSHMK 项目声明了可执行的 GitHub 安装命令，却没有把仓库固定到经过验证的 Commit。原生 HUB 会无条件拒绝这些候选，即使用户明确选择了一键安装；旧路径也不会把源码真正安装到 DSH Web Profile。

## 决策

对于没有精确验证 Commit 的可执行 GitHub 候选，HUB 将其标记为 `one-click-unpinned`。Web 界面先显示圆角确认层；只有确认路径才会向原生启动器发送 `allowUnpinned: true`，取消不会启动安装请求，失败后的重试会保留这次放行决定。

确认后，启动器核对仓库身份，尽可能解析 GitHub 默认分支及当前 HEAD，下载 codeload 源码归档，并继续使用现有 DSH Setup/Profile 引擎安装。生成的 Manifest 会记录仓库、分支、实际解析出的 Commit（如果有）、审核决定、资产 URL、字节数和 SHA-256。如果 GitHub 元数据无法解析，则回退到目录提供的默认分支归档，并记录该来源已由用户确认但未固定。

## 备选方案

**继续拒绝所有未固定 Commit 的 GitHub 候选。** 不采用，因为这会阻止用户明确要求的一键安装路径，即使该 DSHMK 条目本身已经提供可执行安装方式。

**不经确认直接安装目录声明的分支。** 不采用，因为移动分支与经过验证的 Commit 有实质区别，用户必须明确授权这种来源策略。

**把目录中的验证 SHA 当作实际安装版本。** 不采用，因为它可能已经过期，或并不对应实际下载的归档；收据应记录解析出的版本和资产摘要。

## 结果

固定 Commit 的候选保持原有行为，并且排序高于未锁定候选。DSHMK 的可安装筛选同时包含两种模式。安装收据记录实际解析出的来源版本，不再直接复制可能过期的目录验证 SHA。Profile 激活核验会接受未锁定安装得到的实际 Commit，同时继续核对仓库身份。
