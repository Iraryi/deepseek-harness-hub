# Agent Note: HUB 收据与 Profile 组件对账

Status: implemented

[English](2026-09-29-hub-profile-inventory-reconciliation.md) | 中文

## Problem

HUB 的已安装页面只读取自己的收据索引。通过 CLI 或其他安装器安装的组件不会出现，而被外部移除的组件可能仍保留过期的卸载操作。安装历史与可观察到的 Profile 内容回答的是不同问题。

## Decision

`PluginInventory` 读取当前 DSH 数据目录及当前用户默认 `.dsh` 目录下各 Profile 的直接依赖与 Bundle 声明。它将主数据目录的声明与 HUB 收据对账，保留收据元数据及不同数据目录／Profile 的身份，不把传递依赖列为插件。发现结果明确返回来源、数据目录、Profile、版本、声明／文件状态与逐 Profile 警告，不修改 Profile 或输入收据。

包清单依次从 Profile、其父目录、数据目录和当前运行时锚点解析。较近的清单损坏时不会悄悄采用另一个运行时版本。Windows 扩展路径只读句柄支持较长的 npm 目录联接路径，不改变宿主策略。包文件存在不等于运行时已激活。

原生桥接先准备收据输入，再将只读扫描派发到 UI 线程之外。HUB 和组件设置页显示发现项、来源／状态标签、配置定位与扫描警告。组件清单刷新在等待和失败时保留结果与搜索。卸载在调用既有操作前重新检查收据与 Profile 的一致性，并拒绝多个收据共享组件的删除。外部行不会继承 HUB 的卸载权限。

该机制补充而非取代[收据保留机制](2026-08-22-hub-library-persistence-across-setup-lifecycle.zh.md)：Profile 无法重建 Setup 来源与可编辑工作区，而收据不能描述全部外部安装。

HUB 与组件设置页渲染同一个组件清单，提供来源、数据目录／Profile、状态及多关键词筛选。设置页刷新失败也保留原页面。诊断复制使用明确的元数据白名单与可选文本降级，不读取原始 Profile 配置。展示快照也会计算卸载资格：不支持的方式、非法或空目标及共享收据所有权会提前禁用操作并解释原因。真正修改前仍以执行器的检查为准。

## Alternatives considered

**只使用收据。** 拒绝，因为外部安装器不创建 HUB 记录，外部卸载也会留下误导状态。

**用 node_modules 遍历替代收据。** 拒绝，因为传递依赖不等于用户安装的插件，文件遍历也无法恢复 Setup 来源或所有权。

**为所有发现路径启用通用卸载。** 暂缓，因为数据目录与依赖所有权不同；提供破坏性操作前需要正确的所属运行时适配器。

**让 HUB 与设置页分别维护管理控件。** 拒绝，因为不同的刷新与筛选行为已经导致设置页丢失可用状态。共用页面使两个入口保持一致。

## Consequences

外部直接组件无需伪造收据即可展示。损坏配置仍可见，不会默默授权删除。Windows 原生 API 增加了平台专属清单读取代码。其他自定义目录、仅 Cordis 配置项、外部组件生命周期操作与实时激活健康仍不在本实现范围内；组件清单测试不能证明整个产品合格。

## Testing

隔离原生测试覆盖两个数据目录、去重、版本、稳定标识、损坏声明／清单、文件不变性和外部移除。离线 npm 测试执行三轮真实安装／扫描／卸载／扫描，不依赖 HUB 收据，并覆盖长路径及目录联接。组件测试覆盖外部行、警告、定位配置、禁用不支持的操作，以及重新扫描失败后的搜索保留。中英文整页测试使用构建后的客户端资产与桥接响应。原生和客户端构建检查集成；像素／DPI、真实安装、Setup 生命周期及官方 Desktop 迁移属于独立验收。测试不得重定向宿主 Shell Folders 或修改真实 Profile。
