# Agent Note：DSHMK 安装抵抗目录候选回退

状态：已实现

[English](2026-08-22-dshmk-install-snapshot-fallback.md) | 中文

## 问题

DSHMK 在线目录可能保留某个项目，但把原本可用的单一安装候选变成多候选或仅本地构建。详情页应展示实时目录，可是用户在浏览和安装之间触发后台刷新时，安装请求不能因为目录变化就丢失已知可用候选。

固定归档的重复安装也会失败，因为 npm 在 Web Profile 中只保存内容寻址的本地 `.tgz` 路径。

## 决策

浏览、详情和实时元数据继续使用在线目录。只有安装动作在当前项目存在受支持的一键候选时才使用当前目录；否则依次尝试本会话上一份快照和内置快照，选择第一个可安装候选。如果都不可安装，则返回终态目录错误，不创建已安装记录。

把经过校验的 Setup 资产 SHA-256 传给 Profile 激活核验。依赖满足以下任一条件即可匹配：本次新加入、名称等于解析出的 npm 包、依赖规格包含仓库或 Commit 身份、缓存路径包含资产摘要，或已安装包的来源元数据与目标一致。

## 备选方案

**在整个 HUB 会话中固定第一次取得的目录响应。** 不采用，因为浏览和详情页会因此无法接收后续修正的元数据、标签与验证结果。

**把安装后存在的任意依赖都视为激活成功。** 不采用，因为无关的既有包可能造成误判，让 HUB 在目标插件没有安装时仍写入已安装记录。

**每次重复安装前清空包管理器缓存。** 不采用，因为这会拖慢安装，而且包管理器把依赖改写为本地归档路径后，仍然不能据此证明来源身份。

## 结果

后台目录刷新可以改进元数据，而不会让已经展示给用户的安装候选失效。过期 DSHMK 候选会明确失败，不会留下半成品 HUB 记录。固定 GitHub 归档的重复安装即使被包管理器改写为本地缓存路径，仍能保持来源归属。

## 测试

扩展 DSHMK smoke 对八个真实插件以及既有侧栏和 Web 客户端案例完成首装与重复安装，并验证实时目录回退、过期 npm 候选的明确失败、激活与包集合稳定性、重复记录防护以及无 Unicode 替换字符。重建 Launcher 与 Setup 后，Full 和 Lite Setup smoke 均通过。
