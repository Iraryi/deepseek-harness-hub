# Agent Note: HUB 安装库在 Setup 生命周期中的持久化

Status: implemented

[English](2026-08-22-hub-library-persistence-across-setup-lifecycle.md) | 中文

## Problem

HUB 把已安装 Setup 记录及其可编辑工作区保存在当前应用数据根目录中。便携模式卸载会保留 `data` 目录，却删除 `portable.mode`，因此后续启动器可能改用标准数据目录；所有记录和工作区仍在磁盘上，但“已安装插件库”会显示为空。`hub/installed.json` 无法读取时也会直接表现为空库，而不会尝试恢复。

## Decision

`AppPaths.IsPortable` 同时识别程序标记和受本项目管理的便携数据。`.dsh-portable-data`、`config.json`、受管理的 `hub` 目录或 `dsh` 目录都可以证明该数据根属于便携安装。安装器在写入首次配置前创建便携数据目录和两个标记；卸载选择保留用户数据时保留这些标记，只有明确选择删除数据时才移除。推荐重装也会根据保留下来的受管理数据选择便携模式，包括旧安装器卸载时删除了 `portable.mode` 的情况。

`hub/installed.json`、`hub/library`、Setup 收据、离线包、账户数据和目录缓存都属于用户数据，独立于可替换的 Runtime 与启动器文件。写入已安装记录时会保留一份有效的 `installed.json.backup`。主索引无法读取时会从备份恢复；现存工作区会重新绑定到当前的 `hub/library/<setup-id>`，因此保留或移动便携数据根后不会继续使用失效的绝对路径。

## Alternatives considered

[Profile 组件清单对账](2026-09-29-hub-profile-inventory-reconciliation.zh.md)以外部组件观察结果补充保留的收据，不重建或替代 Setup 历史。

**把 HUB 记录作为程序文件放在 EXE 旁边。** 拒绝，因为更新、修复和卸载需要自由替换该目录中的二进制文件，不能让用户管理的 Setup 工作区承担被覆盖风险。

**只根据 DSH Profile 依赖重建已安装状态。** 拒绝，因为 Profile 不保留 Setup 清单、来源、收据、可编辑工作区、卸载元数据，也不能稳定地把一个包依赖映射成一个 HUB 项目。

**保留便携数据时仍删除便携标记。** 拒绝，因为删除标记会让数据归属变得模糊，并导致启动器选择另一个根目录。旧内容检测只作为恢复路径，不是正常身份机制。

**自动把保留的便携数据复制到标准数据根。** 拒绝，因为两个根可能都包含有意保留且版本不同的状态。重装继续使用选定的数据根，不合并无关的会话、凭据或插件记录。

## Consequences

[Setup 保留辅助脚本](../../../../windows/setup/README.zh.md)在保留数据重装时保留配置原始字节，替换后保留上一份 Runtime。数据根选择遵循自定义应用目录，隐式标准/便携迁移被阻止。持久化事务记录会阻止重试，直至中断的切换得到检查。这些保护不实现会话格式迁移，也不保证旧 Runtime 内修改过的插件会自动激活。

更新和修复只替换程序与 Runtime 文件，同时保留已安装 Setup 库。默认卸载后，程序目录可能因为便携用户数据及其身份标记而继续存在，这是预期行为。明确选择删除数据时会删除标准和便携数据根以及便携标记。已安装记录恢复会保留一份此前有效的快照，并优先使用当前 HUB 库根下实际存在的工作区。

## Testing

切换测试通过独立监视进程在校验与切换期间占用暂存目录内的文件，再释放占用。有期限的重试完成同目录切换并保留旧 Runtime；持续占用仍以不替换旧版本的方式失败。这模拟 Windows 短时句柄争用，不代表已查明某次用户目录被哪个应用占用。封装的 Runtime 还需要真实压缩包替换检查，仅报告版本的可执行夹具不能证明其行为。

隔离的[保留测试](../../../../windows/setup/tests/verify-upgrade-retention.ps1)使用仅报告版本的 Runtime 夹具执行生产 Setup 脚本，并对比标准、便携和自定义数据根的文件哈希。它覆盖压缩包/目录替换及对损坏、占用和中断状态的无损拒绝。这些检查不运行历史安装器、不启动应用，也不代表官方 Desktop 迁移已验收。禁止在用户电脑上运行修改宿主环境的旧 smoke 脚本。

Windows 启动器构建会编译便携根识别和已安装记录恢复路径。针对 HUB 的测试通过原生快照读取保留记录，破坏主索引后从备份恢复，并把失效工作区路径重新绑定到当前目录。Setup 测试覆盖标准模式更新保留，以及多轮便携安装、更新、保留数据卸载、无标记旧版重装、原生 HUB 读取和明确删除数据。Full 与 Lite Inno Setup 资产由同一套 hotfix 源码和封装 Runtime 编译。
