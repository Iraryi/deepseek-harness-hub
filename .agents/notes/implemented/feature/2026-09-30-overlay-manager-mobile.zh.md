# Agent Note: Overlay 管理与显式手机访问

Status: implemented

[English](2026-09-30-overlay-manager-mobile.md) | 中文

## 问题

完整内置发行包不能同时满足保留已有 DSH 安装的用户。HUB 需要实际可用的管理操作，而不是仅有路线图的开关，同时不能重写用户会话或默认把本机服务公开到网络。

## 决策

Overlay 使用独立安装器身份、自有程序文件、状态目录以及明确的本体、Runtime 和 home 绑定。版本化适配器通过进程级 Node 解析器重定向指定的已构建包，包含 CONFIG 交接后的原生服务启动。本体 EXE 和 Runtime 不被替换。Full 继续作为独立发行形式。未验证的 Runtime 需要适配器，而不是猜测迁移方式。

HUB 管理侧栏提供只读运行信息、可选桌面增强和手机访问。增强设置通过独立文件、版本检查、精确旧文件备份和原子替换保存，并保留未知字段。宽度、富文本粘贴和可选会话标识使用可清理的显示适配器，而不是修改会话数据。同一个 WebView 中服务重启后，就绪回调会重新应用已保存设置。未保存编辑时，页面离开和原生关闭均受提示保护；CONFIG 保留独立与内嵌形式。

手机访问是显式开启的私有 IPv4 HTTP 中继，复用已有 DSH 界面。短期单次配对凭据创建可撤销的设备会话；HTTP 请求和 WebSocket 升级均在联系 DSH 前进行鉴权。中继在内部交换 DSH 启动令牌，并仅在内存保留 Cookie。桌面发现信息通过当前用户 DPAPI 保护启动 URL，并绑定存活的所属进程。公开状态不含凭据。停止中继或退出 HUB 会关闭所属连接和子进程，不修改防火墙或 Shell Folder 设置。

## 考虑过的替代方案

替换本体安装会让增强层卸载与回滚接管无关文件。复制完整替代 Runtime 只是换名的 Full。根据文件名推测会话格式存在数据损坏风险。把未鉴权的本机 URL 直接用于局域网会绕过原本的本机信任模型。强制冻结进程可能保留文件锁并中断工作。

## 后果

HTTP 不加密，配对不能抵御恶意局域网监听者。界面要求明确同意可信局域网访问，说明完整操作权限，并提供撤销与停止；DSH 已接收的任务不会被取消。TLS、公网隧道、微信、任意官方 Desktop 版本及会话格式迁移均不属于此适配器的隐含能力。原生窗口设置和有界预加载继续可用。保留已有供应商控制与上游滚动恢复，不用空开关替代它们。

## 验证

Full 和 Lite 显式安装相同的增强及手机连接启动器资源；逐文件清单检查拒绝缺失条目或错误目标目录。Full 的 Runtime 内置配套客户端构建包，管理和手机连接不要求先安装 Overlay。显式条目避免把开发者启动器目录中的测试夹具或凭据递归封入安装器。

验证覆盖隔离设置的冲突、备份、校验和加密端点发现，真实输入框粘贴与适配器清理，中英文装配管理操作与受限浏览器布局，带鉴权的 HTTP/WebSocket 配对、过期、撤销和关闭，以及复制 Runtime 上的 Overlay 路径隔离、保留行为、解析器选择和实际提供的包身份。工程 Setup 编译不等于安装升级或实体手机验收。夹具位于 D:，不修改宿主注册表或真实用户 Profile。
