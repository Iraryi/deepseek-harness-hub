# Agent Note: 带草稿离开保护的内嵌桌面 CONFIG

Status: implemented

[English](2026-09-30-embedded-desktop-config.md) | 中文

## 问题

独立启动的 CONFIG 可能被 HUB 遮住，而且独立编辑器不参与设置页的导航生命周期。用户需要可见的待保存状态、明确的保存／重启、离开保护以及可选红黄绿标题栏，同时保留独立的 DSH／HUB 配置和首次设置程序。

## 决策

HUB 插件贡献 CONFIG 设置分区，并在独立工作台使用同一编辑器。所属外壳提供可选异步离开守卫。编辑器保留局部草稿，提供继续、放弃或保存并离开；保存失败保留草稿。保存并重启先写入选定对象，成功后才请求重启。普通浏览器会话不能编辑原生配置。

原生编辑器依据已知字段校验白名单补丁，检查文件 SHA-256 版本，保留无关及未知字段，并在备份上一份文件后原子替换。DSH 与 HUB 仍为独立文件。配置重启在保留实例互斥锁的情况下重新创建选定的原生窗体及托管服务；兄弟程序重新配置使用独立信号，不关闭发起方。运行中的 Setup 阻止重新配置。这不是会话格式迁移，也不是切换到官方 Electron 基线。

独立 CONFIG 接收调用窗口作为原生所有者，并显式置前。兄弟程序启动携带数据目录、本体数据目录及实例参数。现有[独立保存并运行交接](2026-08-21-config-shell-handoff.zh.md)继续用于首次配置，不被内嵌编辑器取代。

红黄绿标题栏分别保存于 DSH 与 HUB 配置。普通窗口拥有原生关闭、最小化、最大化按钮，支持标题拖动和边缘缩放。全屏模式保留既有控件。系统标题栏仍为默认项，红色关闭操作遵循配置的托盘／退出策略。

## Alternatives considered

让 CONFIG 永久置顶会遮住无关程序。移除独立 CONFIG 会破坏首次引导及原生文件选择。从 Web 界面整份替换配置会丢失界面不认识的字段。全局拦截点击会阻塞无关控件并耦合功能包，因此由设置外壳仅保护自己的导航。

## Consequences

保存并离开将原生设置的应用推迟到所选程序下次启动。保存成功但重启失败时，配置仍已保存并提供重试。存在草稿时，原生关闭使用默认取消的确认。版本冲突会显式呈现，不静默合并；不遵守该协议的外部写入方不属于事务参与者。

## 验证

专项测试覆盖草稿状态、先保存再重启、保存失败保留、对象切换、离开决策及设置外壳关闭路径。构建后集成测试覆盖中英文及 DSH／HUB 入口。隔离的 D: 原生测试覆盖数据保留、无效值、冲突、备份和配置对象隔离。1024x768 深浅色静态渲染检查编辑器及决策排版；屏幕外原生渲染检查标题栏控件。这些检查不等同于真实安装路径前后台顺序、负载下跨进程重启或完整 DPI／全屏矩阵验证。测试不修改 Setup 包或宿主安装。
