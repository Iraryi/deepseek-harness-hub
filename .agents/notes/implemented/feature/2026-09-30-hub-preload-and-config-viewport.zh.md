# Agent Note: 有界 HUB 预加载与 CONFIG 视口

Status: implemented

[English](2026-09-30-hub-preload-and-config-viewport.md) | 中文

## 问题

外层带留白的滚动容器会使表单控件从吸底 CONFIG 操作栏下方露出。另开 HUB 进程也会让服务和渲染器启动重复落在用户的导航等待路径上。

## 决策

CONFIG 自行管理全高弹性视口，将滚动表单与不滚动的底栏分开。设置外壳移除标记视口周围自身的留白和滚动。HUB 系统侧栏打开同一个带离开守卫的编辑器；独立 CONFIG 保留。

HUB 偏好新增默认启用、用户可关闭的 `PreloadOnDesktopStart`。本体收到结构化 Web UI 就绪信号五秒后，以相同数据、本体数据与实例参数请求独立隐藏 HUB。已有 HUB 忽略预加载请求。后台启动不显示任务栏入口、托盘图标、重复实例提示或启动错误弹窗。启动和目录刷新共用一分钟预算，HTTP 获取可以取消，取消后的目录不会提交；已有快照保留。

就绪的后台 HUB 先隐藏 WebView 控件，等待可见性处理后请求渲染器休眠。这里使用 [WebView2 页面休眠](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2.trysuspendasync?view=webview2-dotnet-1.0.4129.50)，不强制挂起 Node 或文件操作。用户激活会恢复渲染器，并接管独立生命周期。未被用户打开的实例观察发起本体的进程，在该进程结束后退出；启动不可用或超时则退回普通的用户主动启动方式。

## 考虑过的替代方案

本体就绪前预加载会争抢关键启动路径的资源。冻结整个进程树可能打断安装并持有文件锁。不断后台轮询会在没有用户导航时增加负担。伪造进度计时器无法改善服务启动延迟。

## 影响

页面休眠期间本地服务仍然运行并占用内存。WebView 休眠属于尽力执行；拒绝休眠时记录日志，不冒称成功。离线或慢速来源保留缓存，一分钟预算不保证目录一定更新成功。预加载尚未完成就打开 HUB，仍需等待剩余启动过程。新前端资源与原生启动器必须一起部署。

## 验证

隔离原生夹具使用复制的真实 Runtime 和独立数据、本体数据目录启动，等待超过预热预算，验证渲染器休眠、重复预加载不激活、同进程唤醒并正常退出。回环 HTTP 夹具验证进行中的请求能够取消。CONFIG 持久化测试覆盖预加载默认值和关闭选项。中英文装配设置测试与真实浏览器几何检查覆盖 1024×768、1440×900 下的滚动两端。这些不代表所有原生 DPI 配置和在线市场网络条件都已合格。测试不会修改宿主 Shell Folder 或真实用户配置。
