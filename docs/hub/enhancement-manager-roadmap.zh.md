# 增强发行版与管理中心计划

[English](enhancement-manager-roadmap.md) | 中文

本文是设计与实现状态参考，不是发布公告。Full 仍为本地 alpha.2/WebView2 发行版；官方 Desktop 集成与 Overlay 安装器尚未成为经过验收的发布产品。原有能力与数据保留要求继续受 [HUB 要求](../../HUB_REQUIREMENTS.md) 约束。

## 产品形式

首个工程实现见 [Overlay](../../windows/overlay/README.zh.md)和[手机访问](../../windows/mobile/README.zh.md)。HUB 包含原生运行检查、宽度／粘贴／会话 ID 设置、受保护的保存以及可撤销设备的可信局域网配对。这并不代表下方全部功能清单已经完成，也不代表任意上游版本均已验证；[实现决策](../../.agents/notes/implemented/feature/2026-09-30-overlay-manager-mobile.zh.md)规定了支持范围。

| 形式 | 管理范围 | 安装规则 |
| --- | --- | --- |
| Full | 托管启动器、Runtime 与 HUB | 面向没有 DSH 的电脑提供完整安装，保留现有更新、修复、保留数据卸载流程。 |
| Overlay，工程预览 | 增强启动器、管理工具、适配器及注册插件 | 要求已有受支持的 DSH，不替换本体 EXE、程序归档或签名，采用独立安装器身份与卸载记录。 |
| HUB 管理中心 | 共享管理界面与适配器 | 扩展已有 HUB，不替换市场，也不另建分叉的配置存储；CONFIG 依旧保留独立 EXE。 |

Overlay 安装先只读检测候选路径，识别真实 Desktop/Runtime 版本，明确选择 Profile 与数据目录，展示支持能力。经过测试的适配器将增强内容安装到自有位置，保留变更前清单，确认实际激活后才提交安装记录。失败仅恢复自己拥有的变更。移除 Overlay 绝不卸载 DSH、删除其会话或碰其它应用。未知本体版本提供诊断，不执行猜测补丁。Full 与 Overlay 互换属于需要重复实例和数据目录检查的迁移，不是简单改 AppId。

已将 [Codex++ 仓库](https://github.com/BigPizzaV3/CodexPlusPlus/tree/070be57b40bb53d4889f5a5bf8bf1c7212aabf63) 作为产品参考，检查启动器入口和核心启动代码。它的外部启动器/CDP 方式并不能证明 DSH 兼容。其[许可证](https://github.com/BigPizzaV3/CodexPlusPlus/blob/070be57b40bb53d4889f5a5bf8bf1c7212aabf63/LICENSE) 为 AGPL-3.0；本计划未复制其实现。

## 能力优先级

| 期望体验 | DSH 实现方向 | 当前状态 |
| --- | --- | --- |
| 健康检查与后端连接 | 真实 Runtime/桥接状态、最近故障和用户触发的修复 | 已实现原生 Runtime、路径与端点概览；更广泛的修复适配器待实现。 |
| 管理工具侧栏 CONFIG | 复用带离开守卫的编辑器及独立 DSH/HUB 配置 | 源码已实现，独立 CONFIG 保留。 |
| HUB 快速打开 | 本体就绪后启动、有界刷新、页面休眠、同实例唤醒 | 源码实现并完成隔离 Runtime 验证，不是零内存服务。 |
| 供应商和模型发现 | 扩展模型设置，按供应商发现、超时和能力报告 | 已有模型设置，发现增强待实现。 |
| Fast/服务档位 | 仅展示当前供应商真正支持的选项 | 不照抄 Codex 专属模型名或不支持的档位开关。 |
| 会话删除、撤销、Markdown 导出及导入 | 使用会话所有者 API，限定范围备份/撤销及格式校验 | 管理扩展待实现，不按猜测的 SQLite 结构修改数据。 |
| 历史会话修复与标识 | 预览诊断、验证时间编码、复制夹具和明确恢复 | 待实现；短 ID 不能证明其编码包含时间。 |
| 对话宽度、位置保留与纯文本粘贴 | 可配置功能插件，保留文件/图片粘贴和每会话滚动锚点 | 已实现宽度与富文本粘贴适配器；保留上游位置恢复。 |
| MCP/插件/SKILL 与脚本 | 扩展保留式库存、真实激活检查、按 Profile 编辑与回滚 | 保留 HUB 基础，外部生命周期适配器待实现。 |
| 外观和桌宠行为 | 可逆主题与可选交互，保留键盘操作 | 已有红黄绿窗口形式，更广泛主题/桌宠集成待实现。 |
| 下一步建议与回答大纲 | 明确触发，展示模型/Token 成本，使用现有任务/会话 API | 待实现，不暗中自动调用模型。 |
| SSH 编辑器链接与上游 worktree | 检测编辑器/Git，变更前展示目标与分支 | 待实现，不自动创建或切换分支。 |
| 手机/微信连接 | 配对、过期、撤销、设备列表及鉴权传输 | 已实现可信局域网 HTTP 手机中继；TLS、公网访问和微信仍为独立后续工作。 |

移动候选包括 [DSH Mobile](https://github.com/guoyihub/deepseek-harness-mobile) 与社区 Desktop 配对实现。它们较新的 Runtime/Profile 假设需要对照当前分支审计适配器后才能复用。“手机连接”不能靠给外链按钮改名交付。

## 交付顺序与验收

1. 先完成响应速度与布局回归：独立底栏、真实浏览器滚动、隐藏预加载、唤醒和父进程退出清理。分别记录冷启动与唤醒，不把任意等待时长当作速度测量。
2. 使用真实适配器加入管理概览与能力清单，再逐步增加会话/导出和界面增强；本体不支持时显示明确不可用原因。
3. 在受支持 DSH 安装副本中验证 Overlay，包括激活、本体文件哈希保留、更新、修复、回滚、卸载和保留数据重装。随后才随 Full 发布 Overlay EXE。
4. 配对手机等网络功能需通过撤销、鉴权和取消测试后再加入。绝不通过修改宿主 Shell Folder 隔离测试。

每项交付操作都需行为测试、装配客户端检查以及受限尺寸下的中英文深浅色布局检查。路线表条目或能力探针不算已实现功能；不可用操作不能伪装成安装或修复成功。
