# dsh-client-ui-setup-hub

[English](README.md) | 中文

管理侧栏提供运行概览、可选桌面增强和显式手机配对。增强设置保存在独立文件中，保存时检查版本并保留备份，需要重启 DSH 生效；未保存时离开会受到提示保护。宽度、富文本粘贴和会话 ID 适配器仅影响 Desktop。手机访问通过设备鉴权、过期和撤销复用现有 DSH 界面，但可信局域网 HTTP 不加密，必须明确同意；参见[手机访问](../../../windows/mobile/README.zh.md)与[Overlay 发行版](../../../windows/overlay/README.zh.md)。原有市场、库存和独立 CONFIG 继续保留。

这是 Web/Desktop“插件”设置中的 DSH HUB 标签页。它按需读取 Setup 目录，支持排序与搜索，并在允许安装前完整展示来源、许可证、数字签名、审核、兼容范围、权限、网络和资产声明。

Windows 还会通过独立的 `dsh-hub.exe` 入口展示完整工作台。该入口直接占用完整 WebView2 画布，不打开浏览器，也不会形成窗口套窗口；它提供原生 CONFIG 与启动独立 `dsh.exe` 主程序进程的操作，并会在高 DPI 的受限窗口中调整导航、筛选、卡片和操作行，避免文字与交互控件遮挡。

独立工作台使用功能区而不是分类区：主页、GitHub 发现、审核目录、当前 GitHub 用户的 Star、我的 Setup 库、离线收件箱、已安装 Setup、Setup 构建器、独立 GitHub 账户功能区与安全中心。主页汇总每个数据面并提供直接打开目录和创建草稿的操作。凭据只能在账户功能区填写；发现页与 Star 页不会显示令牌输入框。

发现页按照明确优先级分成三个来源。DSHMK 是默认的第一顺位来源，社区精选市场是经过筛选的后备来源，GitHub 全域仍只承担候选发现与本地 Setup 构建输入，不作为安装捷径。DSHMK 会读取在线目录与详情元数据、写入最近一次可用缓存，并在断网时回退到随程序携带的 2,888 项快照；标签与分类来自同步后的来源元数据，而不是把完整分类体系硬编码进 HUB。有缓存时先立即显示，再由原生层后台刷新在线目录；刷新成功后会通知页面并自动把来源徽标更新为在线，不需要重启 HUB。社区精选市场则独立读取在线 `awesome-dsh-plugin` 目录、写入本机缓存并回退到自身的随包快照。

DSHMK 与社区精选浏览都提供多语言搜索、分类与验证筛选、热度／时间／名称排序、持久保存的 12、24、48、96 或 200 条分页、相邻页码和有界加载重试。DSHMK 卡片默认在一键 Setup 旁提供独立的“项目详情”按钮，CONFIG 可以恢复点击整张卡片进入详情。详情包含来源、许可证、验证证据、声明、权限、兼容范围、版本、安装参考、相关项目与醒目的一键 Setup；CONFIG 还会独立选择侧边副驾驶、主题模态层或全画面详情，也可以要求在应用内承载原网站内容。关闭详情后会恢复进入前的筛选、页码和滚动位置。

一键 Setup 不会把解压到 HUB 库误当成安装，也绝不会执行目录中的命令文本。原生启动器会解析固定 GitHub Commit 或 npm 版本，只允许从支持的资产主机下载，限制资产为 256 MB，计算 SHA-256，把资产放进 CLI 的内容寻址缓存，再生成普通 Setup 清单。Setup 式进度界面统一负责预检、下载、解压、依赖安装、profile 修改、Bundle 激活、安装后验证、日志、超时、取消、重试与最终复位。成功激活后会写入收据，并在需要时静默重载正在运行的 Desktop 服务；无法通用证明的 monorepo 或自定义命令场景会回退到本地 Setup 构建器。

用户可以在独立账户功能区通过访问令牌连接 GitHub，以读取账户和 Star 列表；令牌会先由 GitHub 验证，再通过 Windows DPAPI 按当前用户加密保存，而且永远不会返回 WebView。Star 和 GitHub 全域结果可以生成交给 AI 协助的本地构建工作区，但 AI 不得编造证据或绕过 Setup 协议。

原生启动器负责 `%LOCALAPPDATA%\DeepSeekHarness\hub`：`library` 保存包含 `setup.json`、`options.schema.json` 与双语 AI 编辑说明的工作区；`offline` 是默认不执行任何文件的投递目录；`installed.json` 记录经 HUB 安装的 Setup。profile bundle 和安装时新增的 profile 软件包具备真实移除操作；独立安装程序在存在经过审核的卸载器前，仍交给 Windows“应用和功能”处理。

认证、GitHub 来源和未验证条目始终具有明确区别。非认证条目必须先在 HUB 显式确认已经阅读证据，再通过一次原生确认。普通浏览器会话可以查看目录，但不能执行安装；桌面 WebView 桥只接受当前回环应用来源的消息、同一时间只执行一个安装，并返回最终结果。

随程序交付的审核目录包含内置完整能力包，以及通过元数据、许可证、压缩包哈希、软件包结构和压缩包安装检查的固定 Commit GitHub 候选。更大的社区市场只是精选发现来源，不是认证机构。其交互与安装设计参考 MIT 许可的 `dsh-market`，随包目录数据来自采用 CC0 的 `awesome-dsh-plugin` 项目；对应声明与启动器一起交付。

侧栏在设置上方提供本地化的插件市场图标，图标对齐及展开／折叠点击区域与设置一致。桌面会话通过原生命令打开或唤起现有 HUB；浏览器会话进入同源 HUB 预览，不因此获得安装权限。

在线刷新失败但已保存目录可用时，界面通过本地化的非阻断提示保留浏览。技术诊断默认折叠，按需展开；工具栏刷新按钮用于重试，提示内部不重复放置操作。

DSHMK 的刷新操作绕过内存目录缓存，并请求 HTTP 重新验证。并发原生刷新请求共用一次传输。刷新期间和网络失败后保留原有卡片，提供重试反馈，并保留筛选与页码。来源生成时间与最近成功同步时间分别显示。从磁盘读取的快照属于缓存，即使它曾经通过网络下载。刷新快照端点无法发现发布方尚未收入快照的变化；持续接收来源变更和自动定时刷新尚未实现。

## 桌面 CONFIG

HUB 系统侧栏、顶栏和常规设置均可进入 CONFIG。表单独立滚动，底部操作区固定占位，字段不会从“保存并重启”下方漏出。HUB 配置提供可关闭的本体就绪后预加载：启动与目录刷新共用一分钟预算，之后休眠渲染页面。本地服务继续运行以便快速唤醒；这不是整进程挂起，也不代表零内存占用。独立 CONFIG 入口保留。

设置中的 CONFIG 分区与 HUB 顶栏打开同一内嵌编辑器。DSH 与 HUB 是独立配置对象；保存前修改只保留为草稿。可用的绿色“保存并重启”操作校验并保存变更字段，再请求重启所选程序。保存失败会保留草稿。离开或切换对象时提供继续编辑、放弃修改、保存并离开；最后一项在程序下次启动时应用已保存设置。原生关闭操作也会提示未保存修改。

原生桥拒绝过期版本、未支持字段及无效值，保留未修改字段，并在原子替换前备份上一份文件。运行路径、扩展、快捷键、分辨率预设、加载、全屏和市场偏好均可编辑。独立 CONFIG 仍用于首次配置和原生文件选择；启动时传递调用窗口作为所有者，并保留显式数据目录、本体数据目录与实例参数。

窗口按钮默认使用系统样式。可选红黄绿样式在普通窗口提供关闭、最小化、最大化／还原，支持标题拖动与边缘缩放；全屏保持既有呈现。DSH 与 HUB 分别选择此样式。关闭遵循已选的退出／托盘策略。

## 组件清单

HUB 与组件设置页共用来源、数据目录／Profile、管理状态筛选，多关键词搜索、结果数量和重置操作。不同数据目录中的同名 Profile 保持为独立选项。两个页面均在刷新或失败时保留结果和筛选条件。复制诊断只导出选定的包元数据和本地路径，不导出原始配置或凭据；剪贴板不可用时展示可选中的文本。共享依赖、缺失目标元数据或不支持的卸载方式会提前禁用操作并解释原因，实际执行前仍进行原生复核。

组件清单合并 HUB 收据与当前 DSH 数据目录、当前用户默认 `.dsh` 目录中的直接依赖及 Bundle 声明。每行区分所属数据目录、Profile、来源和声明／包文件状态；收据或包文件均不能证明运行时已激活。外部组件提供定位配置与复制路径操作。重新扫描反映外部变更，不替换保留的收据；等待或失败时保留搜索条件和之前的结果。无法读取的 Profile 会产生可见的部分扫描警告。

外部组件的启用、禁用、更新和卸载需要所属运行时适配器，本扫描器不提供这些操作。任意其他数据目录、未声明包依赖的 Cordis 配置项暂不属于发现范围。[组件清单决策](../../../.agents/notes/implemented/bug-fix/2026-09-29-hub-profile-inventory-reconciliation.zh.md)规定对账和验证边界。

## 已知限制与后续工作

- 审核 Setup 目录仍随受签名保护的 Web 资产交付；更大的在线社区目录只提供发现元数据，不能自行声明 DSH 认证。
- 下载阶段已经提供有界进度与日志；对于无法报告稳定内容长度的来源，精确传输字节进度仍属于后续工作。
- GitHub 登录目前使用用户提供的访问令牌。项目注册 OAuth App 并获得客户端 ID 后，才能用 OAuth 设备流替换该兼容方案。
- 本包不发布 `./invariant` 伴生模块：界面只渲染已验证的声明，不拥有需要单独观测的运行时关系。
